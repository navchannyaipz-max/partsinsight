# Експеримент E1: незалежна перевірка якості

## Що порівнюється
* **baseline** — з відповіді джерела на *початковий* запит відбираються пропозиції з точним нормалізованим артикулом (порядок видачі джерела).
* **partsinsight** — повний пошук застосунку: розбір запиту, розширення за зв’язками аналогів (додаткові звернення за артикулами аналогів), нормалізація, рівні відповідності, групування, ранжування.
* Обидва методи працюють з **одним збереженим знімком збору**. Оцінювання повністю офлайн: не використовується поточний кеш, архів чи пізніші правки довідника; безкоштовний RapidAPI-довідник у E1 не підмішується (використовуються лише зв’язки, зафіксовані під час фіксації).
* Запити до джерела формує та сама функція `service.plan_queries`, що й у застосунку.

## Структура запуску
Кожен запуск — окрема папка `experiments/e1/runs/<run_id>/`: `frozen.json` (запити, джерела, зв’язки аналогів, налаштування, контрольні суми, перелік усіх звернень), копії `queries.csv` і `config.json`, `responses/` (кожна відповідь: джерело, фактичний текст запиту, час, статус `ok` / `ok_empty` / `failed`, записи), `collect_log.csv`, `evaluation/`. Зміна будь-яких умов = **новий запуск** з іншою назвою; старі знімки й розмітка не змінюються.

## Команди
Скрипти запускайте з папки проєкту інтерпретатором з середовища застосунку.

**macOS (Terminal)**
```
cd ~/Downloads/partsinsight
PY=~/PartsInsightData/venv/bin/python
$PY experiments/e1/freeze.py  --run-id e1-2026-12 --sources "Назва джерела 1;Назва джерела 2"
$PY experiments/e1/collect.py --run-id e1-2026-12
$PY experiments/e1/evaluate.py --run-id e1-2026-12
$PY experiments/e1/labels.py  --run-id e1-2026-12
$PY experiments/e1/metrics.py --run-id e1-2026-12
```
**Windows (cmd)**
```
cd %USERPROFILE%\Downloads\partsinsight
set PY=%USERPROFILE%\PartsInsightData\venv\Scripts\python
%PY% experiments\e1\freeze.py  --run-id e1-2026-12 --sources "Назва джерела 1;Назва джерела 2"

%PY% experiments\e1\evaluate.py --run-id e1-2026-12
%PY% experiments\e1\labels.py  --run-id e1-2026-12
```

Назви джерел беруться точно як у вебзастосунку («Вхід» → «Джерела»). Ключі вже введені у «Ключі» — скрипти читають їх з тієї самої бази.

## Порядок
1. **Підтвердити запити.** Відкрийте `experiments/e1/queries.csv`. Для кожного з 20 запитів заповніть `expected_rule` (правило релевантності), `rationale` (обґрунтування) і `evidence_source` (каталог/картка, що це підтверджує), далі змініть `status` з `ЧЕРНЕТКА` на `ЗАТВЕРДЖЕНО`. Твердження про **взаємозамінність** (аналог) потребує незалежного каталожного джерела; без нього залишайте правило «точний збіг артикула» (так звужено Q01 і Q02) або лишайте чернетку. `freeze.py` відмовить, якщо: не 20 унікальних ID Q01–Q20, не по 5 запитів у категоріях full / variant / partial / text, порожнє правило чи обґрунтування або хоча б один статус «ЧЕРНЕТКА».
2. **freeze** — зберігає перелік запитів, вибрані джерела, зв’язки аналогів, налаштування джерел (секрети не зберігаються), контрольні суми коду й **повний перелік звернень** (початкові + за аналогами).
3. **collect** — збирає відповіді. Перед роботою перевіряються контрольні суми (запити, конфігурація, компоненти пошуку, налаштування джерел). Розрізняються `ok`, `ok_empty` (успішна нульова видача) і `failed`.
4. **Невдалий збір:** якщо `collect.py` завершився кодом 2 («Збір неповний»), просто запустіть ту саму команду ще раз — повторюються **лише пропущені або невдалі звернення**, успішні не чіпаються.
5. **evaluate** — виконується лише за повного збору. Якщо бракує відповіді, команда завершується помилкою з назвою запиту й джерела і **не змінює** попередніх таблиць. Результат: `evaluation/expert_sheet.csv` і `evaluation/methods_internal.csv`.
6. **Розмітка.** Розмічайте **лише** `evaluation/expert_sheet.csv`: у колонці `рішення` — `так` / `ні` / `сумнівно`, у `підстава` — причина (обов’язково для «сумнівно»). Експерт бачить запит, правило, бренд, артикул і посилання; метод, позиція та висновок алгоритму приховані; кожна пропозиція запиту розмічається один раз (рішення переноситься на обидва методи автоматично). Повторний `evaluate` не втрачає вже зроблену розмітку.
7. **labels** — переносить рішення на позиції обох методів (`evaluation/e1_table.csv`).
8. **metrics** — перевіряє таблицю й створює `e1_report.md`. Звіт **блокується**, якщо для комбінації «метод + запит + позиція» немає рівно одного рядка, є невідоме рішення або нерозмічена пропозиція, або збір неповний.

## Формули
Hit@1 = кількість запитів із підтвердженою першою позицією / 20. Precision@5 = кількість підтверджених позицій у топ-5 / 100 для кожного методу. Порожня позиція в успішно отриманій видачі дає нуль; пропущене спостереження блокує розрахунок. Окремо звітуються порожні видачі та сумнівні оцінки.

## Тестовий запуск
`python experiments/e1/control_run.py` проходить увесь шлях (фіксація → збір зі збоєм → відмова → повтор → оцінювання → розмітка → звіт) на синтетичних даних. Усе позначене «ТЕСТОВИЙ ЗАПУСК» і не є результатом експерименту. Приклад виводу: `docs/E1_kontrolnyi_progin_TESTOVYI.txt`. Результати реальної вибірки подаються окремо від локального експерименту на 48 запитах.

## Автоматичний прогін (рекомендовано)

Подвійний клік на `e1.command` (macOS) або `e1.bat` (Windows) у корені проєкту — або `python experiments/e1/run_all.py`.
Скрипт сам: перевіряє запити → фіксує умови (усі увімкнені реальні джерела) → збирає відповіді (3 спроби, повторює лише пропущене) →
готує аркуш експерта → після розмітки переносить мітки та рахує Hit@1 / Precision@5. Запуск можна повторювати — він продовжує з місця зупинки.
Лише людина виконує: (1) статус запитів «ЗАТВЕРДЖЕНО» в `queries.csv`; (2) заповнення «рішення»/«підстава» в `expert_sheet.csv`.
Після цього `e1.command` також запускає `experiments/f4_check.py` (живе джерело → кеш → змодельований збій), результат у `experiments/f4_result.md`.
